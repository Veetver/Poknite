# Протокол Poknite v2

Сервер и клиенты 0.2 обновляются совместно. `/v1` и его подмаршруты возвращают HTTP `426 upgrade_required`. Регистрация остаётся по одноразовому приглашению. HTTPS/WSS проверяют сертификат и имя сервера; перенаправления отключены. Токен устройства передаётся в `Authorization: Bearer …`, в URL его нет.

## Модели и разрешения

`User`: `id`, уникальный `name`, `color` в виде `#rrggbb`, `disabled`, `roles` (ID), `actions`. ID неизменяемый. Случайный RGB назначается при создании и миграции, сохраняется в профиле; клиент принимает также три числа 0–255 через запятую. Изменение ника/цвета обновляет авторов локальной истории по ID. У публичных профилей других пользователей списки ролей и действий пустые.

`Role`: `id`, `name`, `allow`, `deny`. Разрешения: `profile`, `contacts`, `direct`, `read`, `send`, `mention`, `manage_channel`, `users`, `channels`, `devices`, `invitations`, `roles`. Разрешения всех назначенных ролей объединяются, любой явный запрет имеет приоритет; отсутствие разрешения закрывает действие. Начальные роли: 1 «Администратор», 2 «Участник», 3 «Читатель». Встроенные роли нельзя менять/отключать, дополнительные можно создавать. Читатель явно запрещает отправку, упоминания и личную переписку.

`Conversation` (в коде также `Channel`): `id`, `name`, `kind` (`channel` / `direct`), `closed`, `actions`. Канальные правила применяются к `read`, `send`, `mention`, `manage_channel`; прежние персональные членства сохраняют разрешения чтения/отправки/упоминаний, но групповой запрет перекрывает их. Администратор обходит канальные правила; запреты его дополнительных глобальных ролей продолжают действовать. Чужие личные диалоги недоступны администратору через API.

Личный диалог определяется уникальной упорядоченной парой ID пользователей. Потеря общего открытого читаемого канала убирает право новой отправки, но сохраняет доступ собеседников к истории. Отключённые пользователи и закрытые каналы сохраняются, ID не переиспользуются.

## Публичный HTTPS

Все маршруты ниже требуют токена, кроме `/healthz` и регистрации:

| Метод и путь | Назначение |
| --- | --- |
| `GET /healthz` | Доступность и версия сервера |
| `POST /v2/devices/enroll` | `{invitation, device_name}` → `{token, device_id, user_id, user_name, retention_seconds}` |
| `GET /v2/profile` | Собственный профиль и доступные действия |
| `PUT /v2/profile` | `{name, color?}`; без `color` прежний цвет сохраняется |
| `GET /v2/contacts` | Участники общих открытых доступных каналов |
| `GET /v2/conversations` | Доступные каналы и собственные личные диалоги |
| `GET /v2/channels` | Алиас списка разговоров |
| `POST /v2/conversations/direct` | `{user_id}` → существующий или новый личный диалог |
| `GET /v2/conversations/{id}/participants` | Доступные участники канала для выбора упоминания |
| `GET /v2/conversations/{id}/e2ee-members` | Читающие активные устройства `{user_id, device_id}`, страницы по 16 |
| `POST /v2/conversations/{id}/messages` | Отправка сообщения |
| `GET /v2/devices` | Собственные активные устройства |
| `DELETE /v2/devices/{id}` | Отзыв собственного устройства |
| `GET /v2/stream?after={cursor}` | WebSocket, курсор ≥0 |

Каталоги контактов, разговоров, участников и административные каталоги пользователей/каналов/ролей возвращают массивы страницами до 16 записей. `?offset=N` задаёт смещение; пустая или короткая страница завершает обход. Клиенты собирают страницы автоматически. Предел ответа/кадра остаётся 32768 байт.

Отправка: `{client_message_id: UUID, text, mentions: [{user_id, start, end}]}`. `text` содержит `e2ee:` и JWE compact конверт до 12288 байт; открытый текст внутри ограничен 4096 байт UTF-8. Формат описан в [E2EE](e2ee.md). Защищённые `cid/sid/did/mid/mentions` должны совпадать с маршрутом, авторизованным устройством и запросом. Хеш состава устройств должен совпадать с актуальными читающими устройствами в транзакции; иначе `409 members_changed`. При `e2ee_required=true` открытая отправка возвращает `426 e2ee_required`. Уже принятый повтор не требует совпадения с новым составом. Диапазоны полуоткрытые, в Unicode code points, а не UTF-8 байтах или UTF-16 единицах. До 32 диапазонов, отсортированы, не пересекаются, клиент проверяет фактические диапазоны после расшифровки, сервер — границы до 4096 и права адресатов; адресат активен и читает канал. Для упоминаний нужно право `mention`. Повтор с тем же устройством и UUID возвращает ту же запись только при совпадении разговора, конверта и всех упоминаний, иначе `409 id_conflict`. Повтор не продлевает TTL.

Сообщение: `id`, глобальный `seq`, `channel_id`, `sender_id`, актуальные `sender_name`/`sender_color`, зашифрованный `text`, `mentions`, Unix-время `created_at`/`expires_at`. После расшифровки клиент проверяет AEAD, метаданные, ограничение 4096 байт UTF-8 и допустимость текста. Локальный ID — `did:mid`, поэтому изменение серверного ID не создаёт повторное уведомление.

## Закрытый административный HTTPS

Эти маршруты отсутствуют на публичном сервисе. Отдельный слушатель требует действующий токен, разрешение роли и фактический IP соединения из разрешённого CIDR. `Forwarded`, `X-Forwarded-For` и другие присланные заголовки доступа не дают. Настройка описана в [руководстве управления](management.md).

| Ресурс под `/v2/admin` | Методы |
| --- | --- |
| `/users`, `/channels`, `/roles` | `GET` каталог, `POST` создание |
| `/users/{id}`, `/channels/{id}`, `/roles/{id}` | `GET`, `PUT`, `DELETE` (отключение/закрытие) |
| `/channels/{id}/rules` | `GET`, `PUT` массив `{role_id, allow, deny}` |
| `/users/{id}/invitations` | `POST` одноразовое приглашение на 15 минут, `DELETE` отзыв всех |
| `/users/{id}/devices` | `GET` устройства пользователя |
| `/devices/{id}` | `DELETE` отзыв устройства |

Пользователь: `{name, color?, roles, disabled}`; канал: `{name, closed}`; роль: `{name, allow, deny}`. Закрытый канал нельзя повторно открыть. Последнего активного администратора с административными разрешениями нельзя отключить или лишить этих прав. Делегированный управляющий не может назначать/изменять права шире собственных. Права перепроверяются внутри транзакции.

## Поток и уведомления

События JSON используют поле `type`:

- `hello`: ID пользователя/устройства и каналы; при большом каталоге `channels` пустой, полный снимок следует в состоянии.
- `state`: полный согласованный снимок `profile`, `contacts`, `channels`.
- `state_part`: большой снимок порциями; `first`, `last`, профиль только в первой части, массивы контактов/каналов. Клиент применяет снимок целиком после `last`, чтобы промежуточная страница не отзывала доступ.
- `profiles`: публичные профили авторов доступной истории и собеседников собственных диалогов. Обновляет ник/цвет независимо от наличия общего канала.
- `message`: `{message, replay, notify}`. `notify=false` для автора; при упоминаниях — `true` только адресатам; без них — другим читающим участникам. То же правило при восстановлении.
- `progress`: просмотренный глобальный курсор, включая пропущенные недоступные записи.
- `reset`: курсор клиента выше текущего сервера, восстановление с 0.
- `synced`: `{cursor, gap}`; восстановление завершено, `gap` означает уже утраченную доступную часть истории.
- `channels`: совместимый снимок списка разговоров.

Клиент сохраняет сообщение, признак `notify` и курсор до `{"type":"ack","cursor":N}`. HTTP-результат собственной отправки не продвигает курсор потока. Дедупликация по ID; серверные `notify=false` никогда не создают уведомления. Восстановление разрешённых уведомлений даёт сводное уведомление. Снимок прав отменяет ожидающие и уже показанные уведомления отозванного канала, ранее полученные локальные тексты сохраняются до очистки. Перед каждой отправкой текста в поток сервер проверяет текущие права и TTL; изменения прав синхронизируются с доставкой.

Один активный поток на устройство: новое подключение отменяет старое. Отзыв прекращает поток и отклоняет регистрацию/отправку/подключение отозванного устройства. Ping раз в 120 секунд, ожидание Pong 30 секунд; запись в сокет не дольше 5 секунд. Восстановление обходит страницы по 50 сообщений без неограниченной очереди.

## Миграции и ограничения

Сервер: версия SQLite 3. Перед миграцией v1 сохраняется `server.v1.<UUID>.backup.db` с правами 0600 через согласованную SQLite-копию; при ошибке миграция откатывается. ID, хеши токенов, курсоры устройств, авторство и персональные членства сохраняются. Клиенты транзакционно добавляют роли разговоров, упоминания черновиков и цвета, сохраняя историю/курсоры/UUID черновиков. Настройки прежнего подключения не меняются.

Сохраняются квоты основной серверной базы 32 МиБ, WAL 4 МиБ, клиентской базы 8 МиБ/1000 сообщений, 60 соединений, 128 одновременных HTTP-запросов, очередь SQLite 64 задания. Лимиты в минуту: 2400 HTTP/IP и текстовых кадров/устройство, 120 подключений/IP, 10 регистраций/IP, 30 отправок/устройство, 30 изменений профиля или создания диалога/устройство, 60 административных изменений/устройство. Неудачные и повторные попытки учитываются.

Ошибки: `{code, message}` на русском; `401 unauthorized`, `403 forbidden`, `409 id_conflict`/`last_admin`/конфликт имени, `426 upgrade_required`, `429` лимит, `507 storage_full`. Истечение TTL прекращает выдачу немедленно, физическая очистка идёт порциями до 256 записей. Новая отправка при заполнении базы не вытесняет действующие сообщения.

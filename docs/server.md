# Установка и администрирование сервера

Готовый сервер для Ubuntu 24.04 на x86_64 входит в `poknite-<версия>-linux-x64.tar.gz` на [странице Releases](https://github.com/Veetver/Poknite/releases/latest). Скачайте этот архив по [инструкции установки](installing.md); сборка из исходников не требуется.

Нужны доступный по интернету адрес, открытый TCP-порт 443, действующий сертификат этого адреса и закрытый ключ. Сертификат должен содержать цепочку промежуточных сертификатов; используйте `fullchain.pem`. Получение сертификата и настройка DNS выполняются отдельно.

Если архив ещё не распакован, распакуйте его и перейдите в каталог `poknite` (пример для версии 0.1.0):

```sh
tar -xzf poknite-0.1.0-linux-x64.tar.gz
cd poknite
```

Из распакованного каталога `poknite` выполните:

```sh
sudo ./deploy/install.sh /path/to/fullchain.pem /path/to/privkey.pem
sudo systemctl status poknite
```

Установка создаёт отдельного пользователя `poknite`, службу systemd и ротацию журнала. Основные пути:

| Назначение | Путь |
| --- | --- |
| Исполняемый файл | `/usr/local/bin/poknited` |
| Настройки | `/etc/poknite/poknite.toml` |
| Сертификат и ключ | `/etc/poknite/cert.pem`, `/etc/poknite/key.pem` |
| База и закрытый сокет управления | `/var/lib/poknite/` |
| Журнал | `/var/log/poknite/server.log` |

Команды администратора выполняйте от того же пользователя, что и служба:

```sh
sudo -u poknite poknited --config /etc/poknite/poknite.toml user 'Анна'
sudo -u poknite poknited --config /etc/poknite/poknite.toml status
sudo -u poknite poknited --config /etc/poknite/poknite.toml invite 1
```

Команда `user` печатает ID пользователя, автоматически добавляя его в общий канал 1. `invite` печатает одноразовое приглашение на 15 минут. Создайте отдельное приглашение для каждого устройства; передайте его пользователю вместе с адресом `https://ваш-сервер`. Не публикуйте приглашения и не помещайте их в общие журналы.

Дополнительный канал и права:

```sh
sudo -u poknite poknited --config /etc/poknite/poknite.toml channel 'Работа'
sudo -u poknite poknited --config /etc/poknite/poknite.toml grant 1 2
sudo -u poknite poknited --config /etc/poknite/poknite.toml ungrant 1 2
sudo -u poknite poknited --config /etc/poknite/poknite.toml revoke 3
```

Подставьте ID, полученные при создании. Изменения прав и отзыв сразу будят активные соединения через закрытый локальный сокет. `status` показывает состояние базы; `systemctl is-active poknite` проверяет процесс. Публичный маршрут `/healthz` проверяет доступность службы, не раскрывая данные пользователей.

## Хранение и ограничения

Начальные настройки: 20 пользователей, 3 активных устройства на пользователя, 60 одновременных соединений, до 64 каналов, текст до 4096 байт UTF-8. Пустой текст и недопустимые управляющие символы отклоняются. Приглашения и токены генерируются криптографическим генератором; сервер хранит их SHA-256 хеши.

`retention_seconds = 86400` задаёт срок хранения новых сообщений. Истёкшие сообщения сразу исключаются из выдачи; физическая очистка выполняется раз в минуту небольшими порциями. База ограничена 32 МиБ, WAL — 4 МиБ. При нехватке места отправка завершается ошибкой: действующие сообщения не удаляются ради новой отправки. Освободившиеся страницы переиспользуются. Ротация оставляет текущий и один предыдущий диагностический журнал; `logrotate` вызывается системным расписанием, поэтому между его запусками возможен небольшой выход за порог 1 МиБ. Тексты и токены не записываются в серверные журналы.

Срок и сертификат можно обновить без разрыва действующих соединений. Скопируйте оба новых файла, установите права и только затем перезагрузите:

```sh
sudo install -m 0640 -o root -g poknite /path/to/new/fullchain.pem /etc/poknite/cert.pem
sudo install -m 0640 -o root -g poknite /path/to/new/privkey.pem /etc/poknite/key.pem
sudo systemctl reload poknite
```

Перезагрузка проверяет срок действия цепочки, корректность сертификата и соответствие ключа. При ошибке продолжает действовать предыдущий сертификат. Также обновляется срок хранения для новых сообщений; старые сохраняют свой `expires_at`. Остальные настройки требуют перезапуска. Автоматическое обновление сертификата должно вызывать эти действия после успешного продления.

Локальная история каждого клиента ограничена 1000 сообщениями суммарно и основной базой 8 МиБ; самые старые локальные записи вытесняются. Временный журнал SQLite и настройки занимают дополнительное ограниченное место. Серверный срок не удаляет уже полученные копии с устройств. Для удаления копий используйте «Очистить историю» на каждом клиенте.

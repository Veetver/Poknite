# Настольный клиент

Скачайте готовый клиент из [последнего релиза](https://github.com/Veetver/Poknite/releases/latest): `poknite-<версия>-linux-x64.tar.gz` для Ubuntu 24.04 на x86_64 или `poknite-<версия>-windows-x64.zip` для Windows 10/11 на x64. Самостоятельная сборка не требуется; выбор файлов и проверка подписей описаны в [инструкции установки](installing.md).

Linux: распакуйте архив и перейдите в каталог `poknite`. Установите системные библиотеки, разместите клиент в постоянном каталоге и запустите его:

```sh
sudo apt install libx11-6 libxext6 libxft2 libxrender1 libxfixes3 libxcursor1 libxinerama1 libxrandr2 libdbus-1-3
mkdir -p ~/.local/bin
install -m 0755 ./poknite ~/.local/bin/poknite
~/.local/bin/poknite
```

Сборка использует X11; в сеансе Wayland нужен XWayland. Для уведомлений необходима обычная пользовательская D-Bus-служба уведомлений рабочего стола. Трей использует StatusNotifierItem, когда окружение поддерживает его; нажатие открывает окно, контекстное меню предлагает открыть окно или выйти. В окружениях без такого трея клиент доступен повторным запуском.

Windows: установите [Microsoft Visual C++ v14 Redistributable x64](https://aka.ms/vc14/vc_redist.x64.exe), если он ещё не установлен, затем распакуйте весь архив в постоянный каталог и откройте `poknite.exe`. Если система сообщает об отсутствии `VCRUNTIME140.dll`, установите этот пакет системных библиотек. Клиент создаёт системные уведомления через Windows API и значок в трее; двойной щелчок открывает окно, меню позволяет открыть окно или выйти. Для текущего пользователя создаются ярлык Poknite в меню «Пуск» и регистрация открытия окна из уведомления, без администратора. Ярлык содержит идентификатор приложения согласно [требованиям Microsoft для desktop-уведомлений](https://learn.microsoft.com/en-us/windows/win32/shell/enable-desktop-toast-with-appusermodelid).

Введите адрес HTTPS, приглашение и имя устройства. Выберите разговор и подключите ключ через «Шифрование» по [инструкции E2EE](e2ee.md). Затем напишите текст и нажмите «Отправить». Крестик скрывает окно, приём продолжается; «Выход» завершает процесс. Повторный запуск открывает существующий экземпляр. Автозапуск включается в настройках и привязан к текущему пути исполняемого файла. При переносе файла отключите и снова включите автозапуск.

Во вкладке «Общение» каналы и личные диалоги находятся слева. Поиск отбирает их по названию; «Новый диалог» открывает контакты. Справа показаны название разговора, история и отдельное поле ввода. Enter добавляет строку, Ctrl+Enter отправляет сообщение. Кнопка `@` выбирает адресата упоминания. «Ранее» открывает старые сообщения, «К последним» возвращает к новым.

Последний выбранный канал или личный диалог открывается при следующем запуске, включая полный выход из приложения. Выбор сохраняется на этом устройстве по ID и остаётся после переименования канала или очистки истории. Черновики сохраняются отдельно для каждого разговора. Если доступ к выбранному разговору исчез, открывается первый доступный. Новое подключение сбрасывает сохранённый выбор.

Настройка «Без звука» оставляет видимые уведомления. Сообщения своего пользователя не вызывают уведомление. После восстановления истории появляется одно сводное уведомление. Вне сети сохраняется черновик; отправьте его самостоятельно после подключения. Неопределённый результат отправки повторяется с прежним ID, предотвращая дублирование в пределах серверного срока.

Linux хранит профиль с токеном в закрытом пользовательском каталоге, Windows шифрует токен средствами DPAPI. Локальная история хранится открытым текстом и защищается правами каталога. Сторонние пользователи устройства не должны иметь доступ к нему.

## Профиль, контакты и управление

Вкладка «Профиль» меняет уникальный ник и цвет: вводите RGB как `255,128,0` или `#ff8000`, либо выбирайте палитру. При создании цвет назначается случайно и сохраняется. В истории и списке контактов ники отображаются этим цветом. Вкладка «Контакты» открывает личный диалог пары; повторный выбор открывает тот же диалог. Ввод `@` в канале открывает выбор участника. Сообщение остаётся видно всем читающим, уведомление приходит только выбранным адресатам; без упоминаний — другим участникам.

Во вкладке «Управление» укажите отдельный HTTPS-адрес и, при необходимости, IP подключения. Операции доступны по текущим разрешениям роли. Настройка LAN/VPN, первого администратора и обновления описана [здесь](management.md).

## Диагностика подключения

Кнопка «Диагностика» проверяет DNS, HTTPS и WSS без приглашения. Она показывает ошибки цепочки/имени/даты сертификата, DNS и сети на русском с подробной причиной. HTTPS и WSS используют один набор Mozilla и доступных системных корней; ошибки загрузки системных корней отражаются в отчёте. Для собственного центра сертификации можно запустить клиент с `--ca /path/ca.pem`; проверка имени сохраняется.

Без интерфейса: `poknite --headless diagnose --server https://pinky.fvds.ru`. Диагностическая проверка старого `/v1/stream` только объясняет доступность сервера 0.1 и необходимость обновления; рабочие и административные запросы всегда используют v2. Проверка на Linux не заменяет воспроизведение первоначальной ошибки на Windows 10/11.

## Сквозное шифрование

Новые сообщения требуют ключ разговора. Подключение, перенос ключей, смена состава устройств и ограничения описаны в [руководстве E2EE](e2ee.md). Обновляйте сервер и оба клиента совместно; старые открытые сообщения и резервные копии не шифруются задним числом.

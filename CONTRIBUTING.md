# Участие в Poknite

Исправления, тесты, улучшения документации и предложения приветствуются. Для значительных изменений сначала откройте issue с описанием задачи и предполагаемого поведения. Небольшое исправление можно сразу предложить в pull request.

## Подготовка

Следуйте [инструкции сборки](docs/building.md). Используйте закреплённые версии инструментов и файлов зависимостей. Для испытаний создавайте отдельную базу и тестовых пользователей; не используйте токены рабочего сервера.

Структура проекта:

| Каталог | Назначение |
| --- | --- |
| `crates/protocol` | Общие модели сообщений и валидация |
| `crates/server` | HTTPS/WSS, хранение и команды администратора |
| `crates/client` | Сетевое ядро и локальное хранилище настольного клиента |
| `crates/desktop` | Интерфейс FLTK и интеграция с Windows/Linux |
| `android` | Нативный Android-клиент |
| `deploy` | Установка и настройки Ubuntu |
| `tools` | Упаковка, интеграционные проверки и замеры |
| `docs` | Пользовательские руководства и справочник протокола |

## Принципы изменений

- Сохраняйте небольшой размер сборок и ограниченное потребление памяти. Новая зависимость должна решать конкретную задачу, которую сложно решить существующими средствами.
- Ограничивайте очереди, объём сетевых данных и выборки из базы. Не добавляйте постоянный опрос там, где доступны события.
- Сохраняйте сообщение на диске до подтверждения получения. Учитывайте повторную доставку, разрыв соединения и заполнение хранилища.
- Не записывайте токены, приглашения и тексты сообщений в диагностические журналы.
- Изменения протокола согласуйте между сервером и обоими клиентами; обновляйте [справочник API](docs/protocol.md).
- Изменения схемы базы должны учитывать существующие установки и сохранность данных.
- Пользовательская документация должна описывать актуальное поведение и воспроизводимые инструкции.

## Проверка изменений

Для Rust:

```sh
cargo fmt --all -- --check
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
```

Для Android:

```sh
cd android
./gradlew --no-daemon test lint assembleRelease
```

Добавляйте тесты, воспроизводящие исправляемую ошибку или проверяющие новое поведение. Для изменений доставки, хранения, уведомлений и фоновой работы выполните соответствующие [интеграционные проверки](docs/verification.md). Изменения интерфейса проверяйте на целевой платформе.

## Pull request

Опишите проблему, поведение после изменения и выполненные проверки. Укажите ограничения проверки, если целевая ОС или устройство недоступны. Для изменений интерфейса полезен снимок экрана без личных данных.

Не добавляйте сборочные каталоги, базы, ключи подписи, сертификаты, токены и локальные настройки SDK. Файлы зависимостей обновляйте вместе с изменениями, которые этого требуют; сохраняйте лицензионные уведомления.

Отправляя изменения, вы соглашаетесь распространять свой вклад на условиях [MIT](LICENSE). Общайтесь уважительно и обсуждайте технические решения по существу.

# Poknite для Android

Клиент уведомлений для Android 8 и новее. Получает сообщения напрямую от вашего сервера Poknite, хранит локальную историю и позволяет отправлять текст в каналы. Для работы не нужны Google Play Services или сторонние push-службы.

## Установка из релиза

Откройте [последний релиз Poknite](https://github.com/Veetver/Poknite/releases/latest), скачайте `poknite-<версия>-android.apk` на телефон и откройте его. Если Android запросит разрешение, разрешите установку из этого источника для браузера или файлового менеджера. Установите приложение и откройте Poknite.

APK уже подписан постоянным ключом проекта: собирать приложение, устанавливать Android SDK или создавать собственный ключ не нужно. Для обновления откройте APK следующего релиза и установите его поверх предыдущей версии. Подробности и проверка подписей — в [инструкции установки](../docs/installing.md).

Архив `poknite-<версия>-android.zip` содержит тот же APK вместе с инструкцией и лицензиями. Используйте полную поставку при дальнейшем распространении приложения.

## Подключение

1. Установите APK из Releases, как описано выше, и откройте Poknite.
2. Введите HTTPS-адрес сервера без пути, одноразовое приглашение администратора и имя устройства.
3. Разрешите уведомления и включите «Приём».
4. Откройте «Настройки → Фоновая работа и батарея» и проверьте разрешения фоновой работы. При необходимости разрешите автозапуск в настройках производителя телефона.
5. Выберите разговор и подключите ключ через «Настройки → Шифрование текущего разговора» по [инструкции E2EE](../docs/e2ee.md).

Приём продолжает работать после закрытия экрана приложения. Постоянное служебное уведомление показывает состояние соединения и позволяет отключить приём. Для отправки выберите канал, введите текст и нажмите «Отправить». Вне сети текст остаётся черновиком; отправить его после подключения нужно вручную.

История прокручивается отдельно, поле ввода остаётся внизу экрана над клавиатурой. Сообщения показывают автора и время; собственные выделены справа. «Ранее» открывает старые сообщения, «К последним» возвращает к новым. Кнопка `@` открывает выбор адресата упоминания. Можно отправлять кнопкой клавиатуры или Ctrl+Enter на внешней клавиатуре.

При следующем открытии, в том числе после завершения приложения, восстанавливается последний выбранный канал или личный диалог и его черновик. Выбор хранится на этом устройстве и сохраняется после переименования канала или очистки истории. Если доступ к разговору исчез, открывается первый доступный. Новое подключение сбрасывает выбор; черновики разных разговоров не смешиваются.

В настройках можно отключить звук, очистить историю и отозвать свои устройства. Локальная история содержит до 1000 сообщений независимо от срока хранения на сервере. Основная база истории ограничена 8 МиБ; временный журнал записи хранится отдельно.

## Фоновая работа

Соединение обслуживает foreground service. На Android 14 и новее служба использует тип `specialUse`. После перезагрузки и обновления приложение восстанавливает ранее включённый приём в пределах разрешений операционной системы. После принудительной остановки необходимо открыть приложение.

Poknite не удерживает постоянную блокировку сна процессора. Энергосбережение Android и ограничения производителя могут задерживать сообщения при выключенном экране. Исключение из оптимизации батареи не гарантирует непрерывную доставку: проверьте поведение на своём телефоне по [руководству проверки](../docs/verification.md#android).

## Сборка

Этот раздел предназначен для разработки и собственных изменений. Для обычной установки используйте подписанный APK из Releases.

- JDK 17 или новее.
- Android SDK Platform 37.0 и Build Tools 36.0.0.
- Доступ к репозиториям зависимостей при первой сборке.

Проект использует Gradle Wrapper; отдельно устанавливать Gradle не требуется. Android Gradle Plugin включает поддержку Kotlin. Интерфейс построен на стандартных Android Views, сеть — на OkHttp.

Из корня репозитория:

```sh
cd android
printf 'sdk.dir=/absolute/path/to/Android/Sdk\n' > local.properties
./gradlew :app:assembleRelease
```

APK без подписи появится в `app/build/outputs/apk/release/app-release-unsigned.apk`. Release-сборка использует R8 и сокращение ресурсов, принимает только HTTPS/WSS и проверяет сертификаты системным хранилищем Android. HTTP-перенаправления отключены.

## Подпись и установка

Подписывайте все обновления одним долговременным ключом. Храните ключ и его пароль вне репозитория и сохраняйте резервную копию ключа. Следующие команды запрашивают пароль интерактивно; `ANDROID_HOME` должен указывать на каталог SDK:

```sh
keytool -genkeypair -keystore /secure/location/poknite.jks -alias poknite -keyalg RSA -keysize 3072 -validity 10000
"$ANDROID_HOME/build-tools/36.0.0/zipalign" -f -p 4 app/build/outputs/apk/release/app-release-unsigned.apk poknite-aligned.apk
"$ANDROID_HOME/build-tools/36.0.0/apksigner" sign --ks /secure/location/poknite.jks --ks-key-alias poknite --out poknite.apk poknite-aligned.apk
"$ANDROID_HOME/build-tools/36.0.0/apksigner" verify --verbose poknite.apk
adb install -r poknite.apk
```

Команду `keytool` выполняйте только при создании нового ключа. APK, подписанный другим ключом, не обновит установленное приложение без удаления старой установки и её данных.

Для автоматической подписи APK в GitHub Actions настройте постоянный ключ в Secrets по [инструкции выпуска релизов](../docs/releases.md). Выпуск по тегу проверяет подпись и SHA-256 отпечаток сертификата перед публикацией; обычные сборки CI остаются без подписи.

## Тесты

```sh
./gradlew :app:testDebugUnitTest :app:lintDebug
./gradlew :app:assembleDebug :app:connectedDebugAndroidTest
```

Для второй команды подключите устройство с разрешённой отладкой USB или запустите эмулятор. JVM-тесты проверяют ограничения текста и URL, а также задержки переподключения. Instrumentation-тесты проверяют SQLite, устранение повторов, квоты, позицию потока, черновики, пересоздание экрана и восстановление выбранного разговора при новом запуске.

Тест доставки через живой сервер требует отдельного тестового сервера и двух свежих приглашений разных пользователей с доступом к одному каналу:

```sh
./gradlew :app:connectedDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.server=https://test.example.org \
  -Pandroid.testInstrumentationRunnerArguments.invitation="$POKNITE_RECEIVER_INVITE" \
  -Pandroid.testInstrumentationRunnerArguments.senderInvitation="$POKNITE_SENDER_INVITE"
```

Перед запуском разрешите уведомления тестовому приложению. Сценарий подключает службу из открытого экрана приложения, закрывает экран, отправляет сообщение вторым пользователем, проверяет уведомление и отзыв устройства. Без аргумента `server` этот сценарий пропускается.

Debug-сборка допускает HTTP только к `localhost`, `127.0.0.1`, `::1` и `10.0.2.2`. Для остальных адресов требуется HTTPS. Для распространения используйте подписанную release-сборку.

## Хранение и безопасность

Токен устройства зашифрован ключом Android Keystore; резервное копирование и перенос данных приложения отключены. Тексты и токены не выводятся в журналы приложения. Сообщение и задание на уведомление сохраняются до подтверждения серверу. Повторно полученные сообщения устраняются по идентификатору, восстановленная история создаёт сводное уведомление только для сообщений с серверным `notify=true`.

Новые сообщения шифруются на устройствах; сервер получает шифротекст и метаданные доставки. Подключение ключей и ограничения описаны в [руководстве E2EE](../docs/e2ee.md). Подробности обмена описаны в [протоколе](../docs/protocol.md), методика измерения памяти и батареи — в [руководстве проверки](../docs/verification.md).

## Ники, цвет, контакты и управление

В настройках «Мой ник и цвет» измените уникальный ник и RGB (`255,128,0` или `#ff8000`). Начальный случайный цвет сохраняется в профиле; ники в истории и выборе контактов/упоминаний окрашены им. «Контакты» открывают единственный личный диалог двух пользователей. Потеря общего открытого канала сохраняет историю и блокирует новые сообщения.

Введите `@` в канале и выберите участника. Диапазоны сохраняются вместе с черновиком, включая Unicode/эмодзи. При наличии упоминаний уведомляются только выбранные адресаты; остальные читающие участники получают сообщение в историю. Собственные сообщения уведомления не вызывают.

«Управление» появляется по разрешениям роли. Задайте отдельный HTTPS-адрес и необязательный числовой IP подключения в настройках. Домен продолжает проверяться TLS, публичный DNS переписки не меняется. При потере LAN/VPN управление сообщает о недоступности, переписка продолжает работать. Сценарий сервера описан в [руководстве управления](../docs/management.md).

В экране подключения есть диагностика DNS/HTTPS/WSS без приглашения; HTTPS и WSS используют один OkHttp-клиент и системное доверие Android. Миграция локальной базы транзакционна и сохраняет историю, курсор, черновики и настройки. Сервер и все клиенты 0.2 обновляются совместно.

## Сквозное шифрование

Новые сообщения требуют ключ разговора. Подключение, перенос ключей, смена состава устройств и ограничения описаны в [руководстве E2EE](../docs/e2ee.md). Обновляйте сервер и оба клиента совместно; старые открытые сообщения и резервные копии не шифруются задним числом.
